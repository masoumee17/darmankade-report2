# انتشار گزارش درمانکده از GitHub روی Vercel

۱. فایل ZIP را از حالت فشرده خارج کن.
۲. محتویات پوشه را در ریشه ریپوی GitHub بارگذاری کن؛ `package.json` و `vercel.json` باید در ریشه باشند و پوشه‌های `api`، `lib` و `scripts` هم همراهشان باشند.
۳. در Vercel، از Add New → Project ریپو را Import کن و Deploy را بزن.

تنظیمات در `vercel.json` آماده‌اند. اگر Vercel پرسید:

| گزینه | مقدار |
| --- | --- |
| Framework Preset | Other |
| Root Directory | ./ |
| Build Command | npm run build |
| Output Directory | public |
| Node.js | 24.x |

این بسته برای پروژه Supabase فعلی تنظیم شده است. حساب‌ها، نقش‌ها و اطلاعات ثبت‌شده در Supabase باقی می‌مانند؛ نیازی به اجرای دوباره SQL نیست. پس از انتشار، هر نفر با ایمیل و رمز حساب خودش وارد پنل می‌شود.

GitHub محل نگهداری سورس است؛ اجرای پنل و APIها در این روش روی Vercel انجام می‌شود. GitHub Pages به‌تنهایی APIهای ورود و ذخیره‌سازی این بسته را اجرا نمی‌کند.

## لینک داکیومنت یا شیت در بلاگ

در پنل بلاگ یا پنل مدیر کل، فعالیت را انتخاب کن، فیلد «لینک داکیومنت یا شیت مرتبط» را پر کن و ذخیره را بزن. در جدول گزارش، کنار وضعیت همان فعالیت دکمه «باز کردن فایل» ظاهر می‌شود. خالی‌کردن فیلد و ذخیره، دکمه را حذف می‌کند. برای فعالیت جدید بلاگ هم همین فیلد وجود دارد.

لینک در ساختار فعلی Supabase ذخیره می‌شود. دسترسی بازدیدکننده به فایل همچنان به تنظیمات همان داکیومنت یا شیت وابسته است.

اطلاعات قبل از ورود، نسخه ثبت‌شده در بسته است؛ آخرین تغییرات تیم پس از ورود از Supabase بارگیری می‌شود.

## اجرای محلی و بررسی

Node.js 24 لازم است. وابستگی خارجی وجود ندارد.

```text
npm test
npm run build
npm start
```

پیش‌نمایش محلی: http://127.0.0.1:4317

آزمون‌ها، محاسبات، ذخیره لینک، حذف لینک، محدوده دسترسی، مسیرهای API و حفظ ورود میان نمونه‌های مستقل سرویس را بررسی می‌کنند. آزمون سرویس از Supabase شبیه‌سازی‌شده استفاده می‌کند. استقرار واقعی روی Vercel باید پس از Import ریپو بررسی شود؛ هنوز منتشر نشده است.

فایل تنظیمات فقط آدرس پروژه و کلید عمومی Publishable دارد. رمز کاربران، توکن نشست، کلید Service Role و فایل‌های موقت در بسته نیستند. در صورت استفاده از پروژه Supabase دیگری، `SUPABASE_URL` و `SUPABASE_PUBLISHABLE_KEY` را در تنظیمات محیط Vercel قرار بده.

مستندات مرجع: [Vercel Node.js](https://vercel.com/docs/functions/runtimes/node-js)، [تنظیمات Vercel](https://vercel.com/docs/project-configuration/vercel-json)، [تأیید هویت در Supabase](https://supabase.com/docs/reference/javascript/auth-getuser).
